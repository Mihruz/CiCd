# Basic CI/CD

Этот проект представляет собой введение в создание простого CI/CD пайплайна для сборки, тестирования и развертывания утилит из проекта SimpleBashUtils. 
Ниже представлено краткое описание задач.

## Основные понятия
**CI/CD** 
* CI (Continuous Integration) — непрерывная интеграция кода.
1. Включает этапы сборки (BUILD) и тестирования (TEST).
* CD (Continuous Delivery) — непрерывная доставка изменений.
1. Включает этапы публикации (PUBLISH), обновления конфигураций (UPDATE CONFIGS) и развертывания (DEPLOY).
* GitLab Runner
1. Инструмент для выполнения задач CI/CD.
2. Регистрируется для конкретного проекта и выполняет этапы пайплайна.


## Задачи
### Часть 1. Настройка GitLab Runner
Установите GitLab Runner на виртуальную машину (Ubuntu Server 22.04 LTS).
Зарегистрируйте Runner для использования в проекте (DO6_CICD).
Используйте URL и токен из платформы для регистрации.
### Часть 2. Сборка
Создайте этап в файле .gitlab-ci.yml для сборки приложений из проекта C2_SimpleBashUtils.
Сохраните артефакты (исполняемые файлы) в произвольную директорию с временем хранения 30 дней.
### Часть 3. Тест кодстайла
Добавьте этап для проверки кодстайла с помощью утилиты clang-format.
Если тест не пройден, пайплайн должен завершиться с ошибкой.
Отобразите вывод утилиты в пайплайне.
### Часть 4. Интеграционные тесты
Напишите этап для запуска интеграционных тестов.
Этап должен выполняться только после успешной сборки и теста кодстайла.
Отобразите результаты тестов в пайплайне.
### Часть 5. Этап деплоя
Поднимите вторую виртуальную машину (Ubuntu Server 22.04 LTS) для развертывания приложений.
Напишите bash-скрипт для копирования артефактов через scp и ssh в директорию /usr/local/bin второй машины.
Добавьте этап в .gitlab-ci.yml для запуска скрипта вручную.
Сохраните дампы образов виртуальных машин.
### Часть 6. Уведомления
Настройте уведомления о выполнении пайплайна через Telegram-бота.
Уведомления должны содержать информацию об успешности этапов CI и CD.
